# 嘉定案例：哪些取舍改善了理解

这是 `high-school-math-visualizations` 的首个试卷案例，不是所有课件的模板。案例选了若干适合动态探究的题；题号、数量、原先的样章审阅安排、库版本与验证次数都不属于通用要求。新试卷必须重新核题和选题。

## 从“能动”到“知道为什么动”

最初较复杂的分幕界面被教师认为花哨，简化为直接操作后，又暴露了新的问题：学生不知道图中对象怎样对应题设与所求。有效修订不是增加教程面板，而是在每题图前补一句短引导，明确对象、操作、目标。

例如：“三个绿色的 1 是题设中的已知距离；改变 AP，观察红色 OA 能取哪些值。”这比“拖动看看会发生什么”更有教学作用。图里标红、读数标红、答案标红应指向同一个所求量，不能只把一个答案数字染色。

教师也明确需要完整答案与规范数学表达。后来把动态近似读数与精确答案区分，将长解析拆成按推理任务命名的短段；分数和根式真正排版，较长公式合理分行。自动横向滚动不是投屏阅读完整证明的理想方式。

## 按理解障碍选择图形

| 嘉定题目中的障碍 | 有效的表达与操作 | 验证时不能遗漏的区别 |
| --- | --- | --- |
| 空间距离约束中看不出 OA 的范围 | 三个单位距离与 OA、AP 同时可见；改变保持条件的构型，旋转只改变视角 | $2OA^2+AP^2=3$ 负责一般范围；对称构造负责可达性。构造中 O、A、P 共线，不代表任意合法构型都共线 |
| 拱桥切线、圆弧怎样成为费用 | 坡角联动切点、切线长度、弧长和费用曲线；需要时放大总费用的局部区间 | 角度单位与长度换算要一致；局部放大必须标清尺度，不能让很小的费用变化看成巨大差异 |
| 绝对值为什么会分段 | 单位圆双点保持夹角，显示到直线的两段垂距；跨线时观察哪项变号 | 找到临界构型只是候选最小值，还需全局证明。不要让点击画布任意位置都误触发拖点 |
| 数列趋近与最终相等混淆 | 蛛网图、项值图、精确初值和逐项计算联动 | 原题差值是否有绝对值；不动点是否精确到达；数值舍入与溢出是否被正确说明 |
| 斜棱柱的侧棱、高和线面平行难以分辨 | 侧棱、垂直高、底面分别标明；标准视角展示线面角；辅助线逐步出现 | 第二问的可变构型不沿用第一问的额外数值条件；旋转看起来平行不能代替线面平行证明 |
| 开区间里极值点进入、离开的临界状态 | 函数图与相位轴联动，连续探索后锁定满足零点条件的离散候选 | 极值点恰在端点时是否计入，取决于原区间的开闭性 |
| 椭圆弦的约束为何固定面积 | 解除与保持约束的对照；将对应对象映射到单位圆，再解释面积缩放 | 斜率未定义的构型不能因交叉相乘而获得合法性；伸缩保留的关系与不保留的长度、角度必须分清 |
| 新定义的全称条件难以读懂 | 联动候选点、函数整体平移后的值域、允许集合及反例点 | 屏幕内没有反例不意味着全称条件成立；窗口外与无穷远行为要用解析论证 |

## 空间图的升级为什么有必要

旧空间投影本身是合法正交投影，问题是丢弃深度后按固定顺序绘制：前后棱同样实、透明面堆叠次序不随观察改变，旋转后标签又会碰撞。单纯换颜色或加材质没有解决这个问题。

本案例后来使用 Three.js 的正交相机、三维网格及射线相交判断，将线段按遮挡拆成可见和隐藏部分，再输出 SVG 面、线与数学标签。这样得到可靠深度关系和清晰的投屏线宽，不依赖 WebGL 能否启用。其他题可以选择 WebGL；技术决定应来自所需关系、画质、兼容性与实测性能，而不是“用某个库就算高级”。

几个有用的细节：

- 题设中的真实物体与构造辅助框要区分。辅助框不能被当成阻挡内部数学对象的不透明实体。
- 相机旋转不重算证明，不重建整个页面；图形对象和标签可以复用，按帧更新视图。
- 标签用实际字体尺寸与候选位置避让，兼顾主要线段；拥挤时允许短引线。不要只靠固定偏移碰运气，也不要只靠字符数估计汉字宽度。
- 标准视角需要实际检查。某个角度恰好把关键线段压得很短，就换一个更能区分对象的初始视角；这不改变数学模型。
- 底面在侧视中投影成线时，不硬把面积标签塞进那条线。可以隐藏该视角的图内面积标注，保留准确读数和解释。

## 验证中真正发现过的问题

检查源码、数值不变量和浏览器断言都不能代替看图。曾需要实际截图才发现：单位长度标签与点名重叠、角度文字被避让到不合适的区域、长公式超出解析栏、低高度窗口压缩了图形，以及曲线确实正确却几乎看不出最优点。

有效的独立复核应拿到原题、实际交付文件和目标使用方式，而非先告诉审阅者“这里已经正确”。发现明确问题后做局部修订，并复查受影响的视图；已通过的无关内容不必反复重测。这个案例的经验是把验证用于排除误解，而非累积检查轮数。
