# 接入试卷与维护 Skill

这份参考只针对 `Pottt651/high-school-math-visualizations` 项目。用于其他工作区时，不创建这里的目录结构，也不要求沿用嘉定源码；先检查该项目现有组织方式。

## 在本项目加入新的试卷

项目名称是“高中数学题可视化”。嘉定只是首个案例：

- 根目录 `index.html` 是试卷入口。
- `papers/catalog.json` 登记可打开的试卷；新增时先读实际字段与现有记录，不凭本参考猜测 schema。
- `papers/jiading-2025/index.html` 是嘉定独立课件。
- 当前 `simple/` 等源码仍服务嘉定案例。可以参考其中的模型与渲染分离，但不要把其题号导航、题目清单或全局对象当成新试卷的默认需求。

为新试卷选择与现有记录一致的标识和目录，保留原有试卷可用。把独立课件与目录入口接起来，检查链接、显示名称以及用户要求的离线打开方式。不要仅在嘉定页面中替换题目文字而留下旧答案、边界、参数范围或题号状态。

作品登记、源码调整和发布是不同动作。是否提交、推送、开启公开页面或上传原卷，以本次会话已有授权为准；此 Skill 不自动扩大授权，也不要求对已授权动作重复确认。

## 仓库副本与个人库同步

仅在用户要求创建、维护、安装或同步本 Skill 的授权范围内执行这一节。普通课件任务不顺带管理技能库。

仓库中可审查的副本为 `skills/math-problem-visualizer/`。个人安装副本位于实际 `CODEX_HOME` 下的 `skills/math-problem-visualizer/`；未配置时通常为用户目录中的 `.codex/skills/math-problem-visualizer/`。不要硬编码某台电脑的用户名，不修改插件缓存。

维护时将有效修改保存在仓库副本，再同步已授权的个人副本。如果个人副本存在不同内容，先比较并合并有意的改动，避免盲目覆盖。保持 `SKILL.md`、`agents/openai.yaml` 与实际引用文件一致；文件清单和内容校验可以确认两份相同。个人目录尚未授权安装时，先完成仓库版本并准确说明同步尚未执行。

修改后运行环境中 `skill-creator` 提供的 `quick_validate.py`。该检查只验证结构，不证明教学决策有效。涉及较大的方法改动时，用另一份题目或新的用户约束做独立前向测试：让测试者在隔离工作区按 Skill 完成一个小而真实的任务，不预先提供期望方案。根据实际失败做窄修订，不把单次审阅意见扩成所有课件的强制流程。
